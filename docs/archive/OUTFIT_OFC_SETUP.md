# OFCアウトフィット項目対応(当時のセットアップ資料)

`supabase/README_22_OUTFIT_OFC.md` と `supabase/README_OUTFIT_OFC.md` を統合した当時の資料。
通常作業では読まない。

OFC固有項目をキャストのアウトフィットへ保存するため、Supabase SQL Editorで次を1回実行する。

```text
supabase/22_outfit_ofc_details.sql
```

このSQLは次を追加する。

- `public.character_outfits.ofc_details`:OFC固有項目を保持するJSON列
- `public.save_character_bundle_with_ofc(...)`:従来のキャスト一括保存とOFC固有項目を同じ
  トランザクションで保存するRPC

## 追加されるOFC項目(`README_22_OUTFIT_OFC.md`より)

共通項目:OFC大分類、OFC小分類、メーカー、参照ページ、隠匿ペナルティ

分類別項目:

- 武器:受、ス、電制
- 防具:制御値、電制
- サイバーウェア:攻、受、射、ス、制御値、電制、防御S/P/I、IANUS部位(表・深・無)、部位
- トロン:ス、制御値、電制、IANUS部位(表・深・無)、トロン値(ソ・サ・ハ)、CS、部位
- ヴィークル:ス、制御値、電制、防御S/P/I、CS、乗員、SF
- 住居:ス、電制、住宅値(登・電・ア)
- その他:攻、受、射、ス、制御値、電制、防御S/P/I、CS、SF、部位

既存のアウトフィットデータは削除・変更しない。従来、解説欄に入っていたメーカー、受、ス、
制御値、電制、防御値、参照ページは、編集画面を開いた際に可能な範囲で追加欄へ読み替える。

## 編集画面の表示ルール(`README_OUTFIT_OFC.md`より)

共通:

- 隠匿値と隠匿ペナルティは、隠匿欄へ`隠匿値/ペナルティ`の形式でまとめる
- `ス`は`スロット`と表記する
- `部位／エリア`は`部位`と表記する
- `外界`列は表示しない

分類別(表示しない項目):

- 武器・防具:OFC大分類・小分類・メーカー
- サイバーウェア:攻・受・射・スロット・防御S/P/I・部位・OFC大分類・小分類・メーカー
  (全身義体は値が存在する項目だけを使用する)
- トロン:IANUS表/深/無、CS値、OFC大分類・小分類、メーカー、参照P、隠匿ペナルティ、
  トロンのソ/サ/ハは列表示せず、値がある場合は解説欄へ記載する
- ヴィークル:OFC大分類・小分類・メーカー・隠匿ペナルティ
- 住居:OFC大分類・小分類・メーカー・隠匿ペナルティ・住宅の電/ア(登は`登場`と表記する)
- その他:外界・攻・受・射・スロット・防御S/P/I・SF・部位・OFC大分類・小分類・メーカー・
  参照P・隠匿ペナルティ・制御値・電制・CS値

非表示項目は既存データとの互換性とOFCマスタ再利用のため、`ofc_details`には保持する。

## OFC検索とTSV

`README_22_OUTFIT_OFC.md`の記述:

- OFC検索から直接追加すると、OFCの全項目を編集画面へ反映する。
- OFC検索の「選択をTSVコピー」は、追加項目を含む拡張TSVを生成する。
- 拡張TSVをOFC TSV取込へ貼り付けると、追加項目も復元する。
- サイバーウェアとトロンは、拡張TSVでも正しい分類へ補正する。
- 従来形式のOFC TSVも引き続き取り込める。

`README_OUTFIT_OFC.md`の記述:

- OFC検索から直接追加すると、必要項目を編集画面へ反映する。
- 隠匿値とペナルティは同じ隠匿欄へ反映する。
- トロンの非表示項目は解説欄へ整理する。
- 拡張TSVにはOFCデータを保持し、再取込時にも復元できる。
- 従来形式のOFC TSVも引き続き取り込める。

## 共通

Edge Functionの再デプロイやOFCマスタの再同期は不要。SQL適用後、編集画面と閲覧画面を強制
再読み込みする。
